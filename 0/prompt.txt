Biggest finding: the neatlogs read API cannot filter traces by custom metadata like run_id or commit_sha, so the PRD's lookup plan needs to change.
  
  **neatlogs SDK** (`neatlogs` 1.4.26 on PyPI, Python >=3.10,<3.14, extra `neatlogs[anthropic]`)
  - **Init:** `neatlogs.init(api_key=, endpoint="https://ingest.neatlogs.com", workflow_name=, instrumentations=[...], tags=[...], user_id=, capture_logs=, sample_rate=, flush_interval=5.0, batch_size=100, mask=, debug=, ...)`. It only takes effect once per process; a second call does nothing. If no key is set, spans are silently not exported.
  - **Anthropic:** the docs now show `client = neatlogs.wrap(Anthropic())` directly. Use either `wrap()` or `instrumentations=[...]`, never both.
  - **End of run:** `flush(timeout_millis=...)` then `shutdown(...)` in a `finally`.
  - **Metadata:**
    - `wrap(client, run_id=..., commit_sha=...)` stamps `neatlogs.workflow.<key>` on the trace root.
    - `with neatlogs.trace(name, kind=, session_id=, **attributes) as s: s.set_attribute(...)` sets attributes on a span.
    - A per-trace workflow label is `root.set_attribute("neatlogs.workflow_name", "...")`.
    - Sessions can be set with `identify(session_id=...)`, `trace(session_id=)` or `@span(session_id=)`.
  - **Spans:** `@neatlogs.span(kind=..., name=, tool_name=, description=, capture_input=, capture_output=)`. Valid kinds are WORKFLOW, AGENT, CHAIN, TOOL, RETRIEVER, EMBEDDING, GUARDRAIL and MCP_TOOL. For a manual non-LLM tool step use `@span(kind="TOOL", tool_name=...)` or `trace("x", kind="TOOL")` plus the `neatlogs.tool.*` attributes.
  - **Current trace ID:** there is no getter. The documented workaround is `c = {}; neatlogs.inject_trace_context(c)`, then take `c["traceparent"].split("-")[1]`. Whether that equals the read API's `traceId` is likely but unconfirmed.
  - **Subprocesses and threads:**
    - A child process can join the parent's trace with `extract_trace_context(carrier, session_id=...)`. Passing the traceparent through a `TRACEPARENT` env var is our own convention, not documented.
    - Session identity is not carried across and must be re-bound in the child.
    - Thread propagation is unconfirmed.
  - **Doctor:** `python -m neatlogs doctor --local --json` needs no network; `--probe --json` uses the key and reads a trace back.
  
  **Trace readback (CLI / Public API)**
  - **Credentials:** the docs say the SDK ingest key does not authorize read API calls. You need a service-account token in `NEATLOGS_TOKEN` (scope `observability:read`), plus `NEATLOGS_HOST=https://app.neatlogs.com` and `NEATLOGS_PROJECT_ID`.
  - **Commands:**
    - `neatlogs --json traces list [--from] [--to] [--status] [--workflow NAME] [--session ID] [--limit ≤50] [--cursor] [--all --max-items N]`
    - `traces search|semantic-search "<q>"` (same filters, no status)
    - `traces get <id>` (metadata only)
    - `traces spans list <id> [--type] [--status]`
    - `traces raw-spans <id>` (input/output previews)
    - `traces payload <trace> <span> --fields input,output,error` (full values)
    - `traces export <id> --format json|markdown|csv`
  - **Public API:** `GET https://app.neatlogs.com/api/v1/public/traces?workflowName&sessionId&from&to&status`, plus `/traces/{id}`, `/spans`, `/raw-spans`, `/spans/{sid}/payload` and `POST /search/traces`. Headers are `Authorization: Bearer` plus `x-project-id`.
  - **No metadata filter:** trace and span responses do not return custom attributes and cannot be filtered by them. Store the trace ID in the ledger and/or put `run_id` into `session_id` so `--session` works.
  - **MCP:** the server at `https://ingest.neatlogs.com/mcp` accepts the project key. Its `get_trace_context` returns the full span tree with inputs, outputs and the detections that fired.
  
  **Detections, Investigate, prompts**
  - **Detections:** can be created from the CLI or API: `neatlogs detections create --group UUID --name --type regex|conditional|pii|classifier --config JSON`. This needs a write-scoped token and a detection group. A regex config takes `input_pattern`/`output_pattern`. A "failed *followed by* issue_refund" sequence across spans can't be expressed as one regex rule (my reading of the schema, not stated in the docs).
  - **Investigate:** dashboard only, with no API or CLI. Fixes and the investigations behind them can only be read through the MCP `triage_*` tools.
  - **Prompts:** versioning and labels work through the SDK (`get_prompt(name, label=)`, `update_prompt(name=, version=, new_labels=)`), `neatlogs prompts ...` and the API. The Playground is UI only and Datasets are "coming soon".
  
  **Entire**
  - **Explain:** `entire checkpoint explain <id|sha>` or `--commit <ref>` resolves through the `Entire-Checkpoint:` trailer. `--transcript` streams the session JSONL.
  - **JSON output:** `--json` gives `checkpoint_id, strategy, branch, checkpoints_count, files_touched, session_count, sessions[{session_id, agent, model, created_at, turn_id, files_touched, token_usage}], tasks`. There is no intent field; intent appears in the text output under `## Intent`.
