Generated by `uv run python scripts/v2_efficiency.py` on 2026-10-10 (branch `feat/v2-efficiency`). The
fixture victim has no LLM: 10 tasks, k = 3, five "fragile" tasks that drop from 0.95 to 0.05 at the
planted commit. Every run below named the planted commit. The numbers are deterministic; a re-run
printed the same table.

What changed in v2:

- **Staged baseline** (`culprit/baseline.py`). Screen every task ×1 on both ends, then run the full k
  only on tasks that did not pass on both ends. Both ends run the same (task, repetition) set, and the
  Fisher gate uses the runs that were actually made.
- **Baseline reuse** (`culprit/reuse.py`). Results at a commit are copied from an earlier run that matches
  on commit SHA, suite SHA, victim provider and model, eval module and k. Each copied row records its
  source run (`reused_from_run`, `reused_from_id`) and is not counted as spend again.

Bisect runs are the same in v1 and v2 on every scenario: the cheaper baseline didn't make the bisect
any harder.

## What this means on the real victim (projection, not measured)

Run `ff50e3620fdd` (v1, `hist/b`, GLM 5.3) made 240 victim runs: 156 baseline + 84 bisect, $0.60.
Its good end was 78/78, and 7 tasks dropped on the bad end. The v2 screen would be 26 + 26 = 52 runs.
Assuming those 7 tasks fail the screen on the bad end, they get the full k: 7 × 2 more reps × 2 ends = 28.
That makes the baseline about **80 runs instead of 156**, and the whole bisect about **164 runs instead of
240 (−32%)**. A second branch from `good-v1.0` with the same suite, model and k would also reuse the good
end (about 40 runs), so it would need about 124 runs (−48%). These numbers will be confirmed by a real v2
run. The fixture's 50% fragile tasks overstate the full-k share compared with RefundDesk's 7 of 26.
